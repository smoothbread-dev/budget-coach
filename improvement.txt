## Suggestions for improvement

**Bugs and correctness**
1. **README is out of date:**
   - It says the AI is Llama 3.1 8B with the key injected by GitHub Actions. The code calls a Cloudflare Worker proxy with `openai/gpt-oss-20b`, and `deploy.yml` only injects the Supabase values.
   - The README lists `GROQ_API_KEY_PLACEHOLDER` but nothing in the code uses it.
   - It omits the Savings tab and the actuals upload.
   - The database schema is missing `savings_categories`, `savings_adjustments`, `plan_savings` and `actual_spending`.
2. **Hardcoded personal Worker URL** in `app.js:2764`. Move it to a config constant. Also make sure the Worker has CORS limits and rate limiting, since anyone can call it from the public site.
3. **Redirect URL hardcoded** in `supabase.js` (`emailRedirectTo`). Use `window.location.origin + window.location.pathname` so it works locally and on forks.
4. **Keep-alive never works:** `setInterval` at 4 days only fires if the tab stays open that long. Use a GitHub Actions cron job that pings Supabase instead. Remove it from client code, or move it to the workflow.
5. **Silent errors:** many save failures only `console.error`. Examples are `saveDefaults`, `saveCurrentMonth`, `addSavingsCategory` and `insertSavingsAdjustment`, which shows `'saved'` on failure. The user thinks the data was saved. Show an error toast and consider rolling back local state.
6. **Optimistic updates:** the recurring item is added to local state before the DB call succeeds.
7. **Deleting a month:** it removes the `month_plans` row and local `plan_savings`, but not the `plan_savings` rows in the DB. Those stay, so `calcCategoryTotalSaved` is wrong after a reload.
8. **Deleting a savings category:** the DB deletes only the category row. Check that the foreign keys cascade, otherwise the adjustments and `plan_savings` are orphaned.
9. **Currency:** "RM" is hardcoded in many places. A currency setting is optional, but at least keep it in one constant.
10. **`escHtml` does not escape quotes.** It is used inside `onclick='...'` attributes with IDs, which are safe today but fragile.

**Security**
- The Supabase publishable key in client code is fine, but only if RLS is enabled on all tables. The README only lists 3 tables, so verify the other 4.
- Pin the CDN scripts with SRI hashes. `@supabase/supabase-js@2` is unpinned.
- SheetJS 0.18.5 from npm has known vulnerabilities (prototype pollution, ReDoS). Use the vendor CDN build or another parser, and limit upload size.
- Send only what the AI needs. Check what the prompt includes, since actuals may include notes or merchant names.

**Code structure**
- `app.js` is a 2,900-line monolith with inline `onclick` handlers on the global scope. Split it into ES modules (state, api, render, ai, savings, actuals) and use `addEventListener`.
- There is heavy inline styling in `index.html`, such as the auth modal. Move it to `style.css`.
- Repeated Supabase load, save and delete patterns could be generalised into a small data-access layer.
- Add basic tests for `calcTotals`, `buildPrompt` and the XLSX parser.

**UX**
- Edit and delete flows still need confirmation consistency. Some deletes use `showConfirm` and others do not.
- Add a loading skeleton on first load. The toast says "Ready" even if loading fails.
- Add a charts view (spending breakdown, savings trend across History).
- Export plans to CSV.
- Add a PWA manifest and service worker, since you already ship an apple-touch-icon.
- Accessibility: modals need focus trapping, Esc to close and `aria` attributes. Buttons that are only icons need labels.
- Support a decimal-safe input and a thousands separator.
- A 600 ms debounced auto-save can lose data if the tab is closed. Flush on `beforeunload` or `visibilitychange`.

## What can be removed or simplified

- **Keep-alive** in client code (see above).
- **`console.log`** in the keep-alive function.
- **`TOAST_CONFIG`/`TOAST_DURATIONS`** next to the unused `TOAST_TIMEOUT` constant. Remove the unused ones.
- **`showAlert`'s `ALERT_CONFIG`** is unused, because `titles` is redefined locally.
- **The "purpose banner" with its session-only dismiss.** Make it a one-time dismiss, stored per user, or drop it.
- **Duplicated empty comment blocks** such as `// ───` in `renderSavingsCategoriesList`, and the "NEW:" and "👈" comments.
- **`initUserMenu` retry loop and cloning trick.** Attach one delegated listener instead. The current code stacks a `document` click listener on every call.
- **The Defaults tab.** Defaults could be a small settings modal in the avatar menu instead of a whole tab.
- **The mandatory goal modal chain** (income, then goal, then defaults prompt). Merge it into one "new month" dialog.
- **Prompt preview button.** This is a developer feature. Hide it or remove it for end users.
- **`sed` injection step** in the workflow. This works, but a `config.js` generated at build time is cleaner.
